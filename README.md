# OnixData

Интерфейс продукта **OnixData** (сервис парсинга публичных данных из
мессенджеров): экраны авторизации, дашборд и управление Viber Parser.

Собран на Next.js 14 (App Router) + TypeScript + Tailwind CSS + готовых
компонентах **shadcn/ui** (стиль `new-york`, исходники лежат в
`components/ui/`).

## Запуск

```bash
npm install
Copy-Item .env.example .env.local
npm run dev
```

Приложение поднимется на <http://localhost:3000> и сразу перенаправит на
`/login`.

Прочие команды:

```bash
npm run build      # продакшен-сборка
npm run start      # запуск собранного приложения
npm run lint       # ESLint (next/core-web-vitals)
npm run typecheck  # проверка типов
```

> Для первой сборки нужен интернет: шрифт **Inter Tight** подключён через
> `next/font/google` и скачивается на этапе сборки.

Для Unix-подобной оболочки вместо `Copy-Item` используйте
`cp .env.example .env.local`.

## Подключение Viber Parser

Страница `/dashboard/viber` работает с Ktor-сервисом из соседнего проекта
`Viber-parser`. По умолчанию серверная часть Next.js обращается к
`http://127.0.0.1:8080`; другой адрес можно задать в `.env.local`:

```dotenv
VIBER_PARSER_URL=http://127.0.0.1:8080
```

Переменная является серверной и не должна иметь префикс `NEXT_PUBLIC_`.
Запустите Viber Parser согласно его README, затем откройте раздел
**Viber Parser** в навигации OnixData.

Next.js предоставляет ограниченный proxy `/api/viber/*`. Он принимает только
операции получения статуса, запуска и остановки сессии, сбора участников,
чтения групп и участников группы. Произвольные пути, методы и query-параметры
к Ktor-сервису не пересылаются.

Операции запуска сессии и обхода участников имеют модель fire-and-forget:
Viber Parser отвечает `202 Accepted`, но не возвращает job ID, прогресс,
результат или ошибку завершения. Поэтому интерфейс показывает только факт
принятия команды и блокирует повторный обход до остановки/перезапуска сессии
либо перехода parser в `IDLE`/`ERROR`.

Группа выбирается из списка Viber Parser по `conversationId`, однако endpoint
`scroll-members` принимает её отображаемое имя. Группу без имени нельзя
запустить из интерфейса; при совпадающих именах backend не гарантирует выбор
конкретной группы. Для каждой группы backend возвращает число активных
участников, декодированных участников и остаток. Декодированным считается
участник с непустым номером без префикса `em` (регистр не важен). В браузер для
таких участников передаются только номер, отображаемое имя и дата рождения;
роли, статусы и внутренние идентификаторы отбрасываются серверным proxy.

## Важно: остальная часть интерфейса остаётся прототипом

- **Реальная интеграция есть только в разделе Viber Parser.** Остальные экраны
  продолжают использовать демонстрационные данные и действия.
- **Авторизация — UI-only.** Формы входа, регистрации и восстановления пароля
  валидируются на клиенте (zod + react-hook-form), но никого не аутентифицируют:
  успешная отправка показывает тост и переводит на `/dashboard`. Роуты дашборда
  и `/api/viber/*` ничем не защищены, поэтому приложение нельзя публиковать в
  открытый доступ без добавления авторизации.
- **OAuth-кнопки — заглушки.** Google и GitHub показывают тост
  «Демо: OAuth не подключён».
- **Все данные — мок.** Источники, сообщения, метрики, график и датасеты лежат в
  `lib/mock-data.ts`. Числа вымышленные и приведены только для демонстрации
  интерфейса, это не результаты реальных клиентов.
- **Действия — заглушки.** Пауза/экспорт/удаление источника, скачивание
  датасета и копирование API-ключа только показывают тосты. Исключение —
  вкладка «Профиль» в настройках: имя сохраняется в `public.profiles` и в
  `user_metadata`, смена email и пароля идёт через Supabase Auth.
- «Живой» поток на `/dashboard/stream` — это `setInterval`, который каждые ~3
  секунды добавляет сообщение из локального набора заготовок.

## Тема и бренд

Приложение работает **только в тёмной теме**: на `<html>` жёстко стоит
`className="dark"`, а палитра продублирована в `:root` и `.dark`
(`app/globals.css`), поэтому переключатель тем не нужен и «вспышки» светлого
фона нет.

Бренд-акцент — коралловый `#ff8975` (переменная `--primary`). Он используется
точечно: ключевые кнопки, активные состояния и данные графика. Логотип —
`components/brand-logo.tsx`.

## Дизайн-система

Правила интерфейса зафиксированы в двух местах:

- [`docs/design-system.md`](docs/design-system.md) — принципы, токены, шкалы
  типографики и отступов, layout-паттерны, каталог компонентов, состояния,
  список do/don't и чек-лист для новых экранов.
- Маршрут [`/design-system`](http://localhost:3000/design-system) — живой
  стайлгайд: свотчи всех CSS-переменных, образцы типографики, шкалы, демо
  анимаций и галерея компонентов на реальных данных. Страница лежит вне
  групп `(auth)` и `(dashboard)`, в навигацию не добавлена; подкомпоненты —
  в `components/design-system/`.

HEX-значения продублированы только в `lib/design-tokens.ts` (для подписей на
странице и в документе). В компонентах цвет берётся Tailwind-классом или через
`hsl(var(--…))`.
